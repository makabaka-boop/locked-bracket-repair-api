# 自动装配机工艺宏修复服务

纯后端 API：把抄录出错（开始/结束标记弄反）的括号宏修复为**类型正确的平衡嵌套序列**。
人工确认过（`locked`）的位置是硬约束，绝不被悄悄放宽。

## 快速开始

```bash
docker compose up --build
# 服务监听 http://localhost:8000 ，交互式文档见 /docs
```

本地开发（Python 3.12）：

```bash
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
pytest            # 运行全部测试（含短串穷举对拍）
```

## API

### `POST /repair`

请求体：`tokens` 为 2–160 个（偶数）token，每项**仅**含 `char` 与 `locked`：

- `char`：`(` `)` `[` `]` `{` `}` 之一；
- `locked`：布尔值（严格校验，`"true"`/`1` 等一律 422）。

任何额外字段、类型错误、长度越界或奇数长度都会返回 **422**。

```json
{
  "tokens": [
    {"char": "(", "locked": true},
    {"char": "[", "locked": false},
    {"char": ")", "locked": false},
    {"char": "]", "locked": true}
  ]
}
```

修复成功（200）：

```json
{
  "status": "OK",
  "repaired": "()[]",
  "pairs": [[0, 1], [2, 3]],
  "changes": [
    {"index": 1, "before": "[", "after": ")"},
    {"index": 2, "before": ")", "after": "["}
  ],
  "cost": 2
}
```

- `repaired`：修复后的整串；
- `pairs`：配对下标 `[开, 闭]`，按开下标排序，覆盖全部位置；
- `changes`：每项改动的前后字符（只含未锁定位置），`cost` 为改动数。

不存在合法方案时（仍是 200）：

```json
{"status": "NO_REPAIR", "repaired": null, "pairs": null, "changes": null, "cost": null}
```

另有 `GET /healthz` 供容器健康检查。

## 修复目标（唯一解）

1. 只改动未锁定位置；
2. **最小化修改数**；
3. 同成本下按显式顺序 `(` < `)` < `[` < `]` < `{` < `}` 取**字典序最小**的结果。

两点目标构成全序，因此答案唯一，可逐位置核验。

## 算法：区间动态规划

不枚举任何替换方案。利用平衡串的上下文无关分解
`S → open_t S close_t S`（t 为三种括号之一），对区间 `[l, r)` 维护
`dp[l][r] = (最小编辑成本, 字典序最小键, 修复串)`：

- 枚举 `l` 的配对位置 `k`（奇数距离）与括号类型 `t`；
- 候选成本 = 改写 `l`、`k` 的代价 + 内部区间 + 剩余区间的最优成本；
- 同成本时比较按显式顺序编码的键串，保留更小者。

锁定位置通过“改写代价为 ∞”建模，因此约束永远不会被放宽。
时间复杂度 O(n³)、空间 O(n²)，n ≤ 160 时单次求解约 150 ms。

## 测试

`tests/` 下 37 个用例：

- **穷举对拍**：n=2 全部输入×全部锁定组合、n=4 全部输入×多种锁定组合，
  以及 n=6/8 随机锁定，与暴力枚举所有替换的参考解逐一比对（成本与字符串完全一致）；
- 全部锁定、交叉闭合 `([)]`、多种同成本修复（如 `]]]]` → `[[]]`，验证 `[` < `]`）等边界；
- 锁定不可放宽：锁定后最优成本上升也不得触碰锁定位置；
- API 层：422 校验矩阵、NO_REPAIR 响应、响应逐位置可核验性。
